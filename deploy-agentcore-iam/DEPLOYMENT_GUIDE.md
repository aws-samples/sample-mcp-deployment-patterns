## Overview

This deployment converts a local FastMCP server into an AgentCore-hosted service accessible via AWS SigV4 authentication. The deployment uses:

- **FastMCP**: Python framework for building MCP servers
- **AgentCore Runtime**: AWS managed service for hosting MCP servers
- **CodeBuild**: ARM64 container builds for AgentCore
- **SigV4 Authentication**: AWS IAM-based security (no OAuth complexity)

## Authentication Architecture

### How Authorization Works

The system uses **AWS SigV4** authentication, which has two distinct layers:

#### 1. MCP Inspector ↔ Proxy (Local Authentication)
```
User Browser → MCP Inspector UI (localhost:6274)
                ↓ (session token in query param)
              Proxy Server (localhost:6277)
```

- **Session Token**: Generated by MCP Inspector when it starts
- **Purpose**: Authenticates the browser to the local proxy server
- **Flow**:
  - MCP Inspector generates token: `<example-session-token>`
  - Token passed in URL: `http://localhost:6274/?MCP_PROXY_AUTH_TOKEN=...`
  - Browser includes this token in requests to proxy
- **Scope**: Only protects local proxy from unauthorized local access

#### 2. Proxy ↔ AgentCore (AWS Authentication)
```
Proxy Server (localhost:6277)
    ↓ (AWS SigV4 signed request)
AgentCore Runtime (AWS)
```

- **AWS SigV4 Signing**: Uses your AWS credentials from `~/.aws/credentials`
- **Purpose**: Authenticates proxy to AWS AgentCore service
- **Flow** (from `agentcore-proxy-sigv4.py:38-63`):
  ```python
  # 1. Get AWS credentials from boto3 session
  session = boto3.Session()
  credentials = session.get_credentials()

  # 2. Create AWS request with MCP payload
  request = AWSRequest(
      method='POST',
      url=AGENTCORE_URL,
      data=body,
      headers={
          'Content-Type': 'application/json',
          'Accept': 'application/json, text/event-stream',
          'x-mcp-session-id': SESSION_ID
      }
  )

  # 3. Sign request with SigV4
  SigV4Auth(credentials, 'bedrock-agentcore', REGION).add_auth(request)

  # 4. Send signed request to AgentCore
  response = await client.post(AGENTCORE_URL, content=body, headers=dict(request.headers))
  ```

- **Headers Added by SigV4**:
  - `Authorization`: AWS4-HMAC-SHA256 signature
  - `X-Amz-Date`: Timestamp for signature validation
  - `X-Amz-Security-Token`: Temporary credentials (if using STS)

- **Scope**: Authenticates to AWS using IAM permissions
- **Required IAM Permission**: `bedrock-agentcore:InvokeAgentRuntime`

### Why Two Layers?

1. **Local Session Token**: Prevents unauthorized local processes from accessing the proxy
2. **AWS SigV4**: Ensures only authorized AWS users can invoke AgentCore runtime

### Alternative: OAuth (Not Used)

We initially tried OAuth with Cognito but encountered issues:
- AgentCore requires BOTH `client_id` AND `aud` claims in JWT
- Cognito tokens provide only one or the other
- SigV4 is simpler and more reliable for this use case

## Deployment Steps

### Prerequisites

1. **AWS CLI configured**
   ```bash
   aws configure
   # Ensure you have credentials in ~/.aws/credentials
   ```

2. **Required AWS Permissions**

   Use a dedicated deployment role and generate its policy from the operations
   observed during a deployment. Do not combine IAM role management and
   service-wide wildcards in a policy with `Resource: "*"`.

   For Python utilities in this sample, IAM Policy Autopilot can generate a
   deterministic baseline:

   ```bash
   uvx iam-policy-autopilot@latest generate-policies \
     "$(pwd)/get-access-token.py" \
     --region your-region \
     --service-hints cognito-idp \
     --pretty
   ```

   The AgentCore deployment itself is performed by the AgentCore CLI rather
   than direct SDK calls in this repository. Run it first in a sandbox account,
   then use IAM Access Analyzer policy generation or its CloudTrail activity to
   create the deployment-role policy. Review the result before attaching it.

   Scope the generated deployment policy as follows:

   - Limit ECR repository actions to the repository used by this sample.
     `ecr:GetAuthorizationToken` is the exception that requires `Resource: "*"`.
   - Limit CodeBuild actions to the generated project ARN.
   - Limit AgentCore actions to this sample's runtime resources wherever the
     action supports resource-level permissions.
   - Limit role creation and updates to a dedicated IAM path such as
     `/sample-mcp/`.
   - Require a permissions boundary when a deployment role creates another
     role.
   - Scope `iam:PassRole` to the exact runtime/build roles and restrict it with
     `iam:PassedToService`.

3. **Python dependencies**
   ```bash
   pip install mcp fastmcp boto3 httpx
   ```

### Step 2: Write MCP Server

The critical configuration for AgentCore (from `src/agentcore_mcp.py`):

```python
from mcp.server.fastmcp import FastMCP

# CRITICAL: These parameters are required for AgentCore
mcp = FastMCP(
    "maths",
    host="0.0.0.0",        # Bind to all interfaces (not 127.0.0.1)
    stateless_http=True    # Enable stateless mode for AgentCore
)

@mcp.tool()
def add_numbers(a: int, b: int) -> int:
    """Add two numbers together"""
    return a + b

@mcp.tool()
def multiply_numbers(a: int, b: int) -> int:
    """Multiply two numbers together"""
    return a * b

# CRITICAL: Use streamable-http transport (not stdio or sse)
if __name__ == "__main__":
    mcp.run(transport="streamable-http")
```

**Key Requirements**:
- `host="0.0.0.0"`: Containers need to bind to all interfaces
- `stateless_http=True`: AgentCore requires stateless operation
- `transport="streamable-http"`: AgentCore's MCP protocol variant

### Step 3: Deploy to AgentCore

```bash
cd infrastructure
./deploy.sh
```

The script will:
1. Load environment variables from `.env`
2. Install AgentCore CLI if needed
3. Configure agent with absolute paths
4. Build ARM64 container via CodeBuild
5. Deploy to AgentCore Runtime
6. Display agent ARN and status

**Expected Output**:
```
✅ Agent deployed successfully
Agent ARN: arn:aws:bedrock-agentcore:region:account-id:runtime/agent-name
STATUS: READY
```

### Step 4: Test with Python

Direct test using SigV4:
```python
import json
import boto3
from botocore.auth import SigV4Auth
from botocore.awsrequest import AWSRequest
import httpx
import asyncio

AGENT_ARN = "arn:aws:bedrock-agentcore:region:account-id:runtime/agent-name"
REGION = "your-region"
encoded_arn = AGENT_ARN.replace(':', '%3A').replace('/', '%2F')
url = f"https://bedrock-agentcore.{REGION}.amazonaws.com/runtimes/{encoded_arn}/invocations?qualifier=DEFAULT"

session = boto3.Session()
credentials = session.get_credentials()

async def test():
    payload = {"jsonrpc": "2.0", "id": 1, "method": "tools/list"}
    body = json.dumps(payload).encode('utf-8')

    request = AWSRequest(
        method='POST', url=url, data=body,
        headers={'Content-Type': 'application/json', 'Accept': 'application/json, text/event-stream'}
    )
    SigV4Auth(credentials, 'bedrock-agentcore', REGION).add_auth(request)

    async with httpx.AsyncClient() as client:
        response = await client.post(url, content=body, headers=dict(request.headers))
        # Parse SSE response
        for line in response.text.split('\n'):
            if line.startswith('data: '):
                print(json.dumps(json.loads(line[6:]), indent=2))

asyncio.run(test())
```

## Key Learnings

### 1. FastMCP Configuration

❌ **Wrong** (default settings):
```python
mcp = FastMCP("maths")
mcp.run()  # Uses stdio transport by default
```

✅ **Correct** (AgentCore requirements):
```python
mcp = FastMCP("maths", host="0.0.0.0", stateless_http=True)
mcp.run(transport="streamable-http")
```

### 2. Transport Protocols

| Transport | Use Case | AgentCore Compatible |
|-----------|----------|---------------------|
| `stdio` | Local CLI, pipes | ❌ No |
| `sse` | Server-Sent Events | ⚠️ Partial (wrong path) |
| `streamable-http` | HTTP with streaming | ✅ Yes |

### 3. Response Format

AgentCore returns **SSE (Server-Sent Events)** format:
```
event: message
data: {"jsonrpc":"2.0","id":1,"result":{...}}
```

You must parse the `data:` line to extract JSON.

### 4. Host Binding

- `host="127.0.0.1"`: Only localhost (❌ fails in Docker)
- `host="0.0.0.0"`: All interfaces (✅ works in Docker)

### 5. Stateless HTTP

AgentCore doesn't maintain persistent connections, so `stateless_http=True` is required.

## Troubleshooting

### Empty Tools List

**Symptom**: MCP Inspector shows no tools

**Causes**:
1. Missing `host="0.0.0.0"` - server not accessible from container
2. Missing `stateless_http=True` - server expects persistent connection
3. Wrong transport - using `stdio` or `sse` instead of `streamable-http`

**Solution**: Verify `src/agentcore_mcp.py` has correct configuration (see Step 2)

### Internal Server Error (-32603)

**Symptom**: `{"code": -32603, "message": "An internal error occurred"}`

**Causes**:
1. Server not running at all (check CloudWatch logs)
2. Wrong transport protocol
3. Missing `mcp.run()` call

**Solution**: Check logs
```bash
aws logs tail /aws/bedrock-agentcore/runtimes/YOUR-AGENT-ID-DEFAULT \
  --since 5m --region your-region --format short
```

### 404 Not Found

**Symptom**: `"POST /mcp/ HTTP/1.1" 404 Not Found`

**Causes**:
1. Using `sse` transport (expects `/messages/` path)
2. Wrong mount_path configuration

**Solution**: Use `streamable-http` transport (default path is `/mcp`)

### Authentication Errors

**Symptom**: 403 Forbidden, signature errors

**Causes**:
1. Missing AWS credentials
2. Invalid IAM permissions
3. Clock skew (timestamp mismatch)

**Solution**:
```bash
# Verify credentials
aws sts get-caller-identity

# Check clock sync
date

# Verify IAM permissions
aws iam get-user
```

### Port Already in Use

**Symptom**: `MCP Inspector PORT IS IN USE at http://localhost:6274`

**Solution**:
```bash
# Kill existing processes
lsof -ti:6274 | xargs kill -9
lsof -ti:6277 | xargs kill -9

# Restart inspector
npx @modelcontextprotocol/inspector python3 agentcore-proxy-sigv4.py
```
